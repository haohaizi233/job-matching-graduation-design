# 11 模型选型（Phase4-3B / B6 前置）

- 证据：`06-retrieval-benchmark.json`、`08-ablation-study.json`、`09-statistical-analysis.json`、`10-resource-benchmark.json`
- **状态：工程选型建议（B 档）；正式模型选型结论 BLOCKED，等待 H2 真实 Gold。**

## 1. 选型纪律

1. 模型选择只允许使用开发/验证口径数据，最终盲测 Gold 不参与选型、早停、超参选择。
2. 当前所有对照均在合成代理标签上，**任何「A 优于 B」都是口径内观察，不是真实求职推荐结论**。
3. 若真实 Gold 上复杂模型不敌简单基线，如实报告并分析原因。

## 2. 口径内观察（合成夹具，仅供工程选型参考）

| 观察 | 依据 |
|---|---|
| 关键词法（TF-IDF/BM25）是强基线，语义召回不占优 | E01/E02 vs E03：B ndcg@5 0.560/0.536 vs 0.364 |
| 规则融合（E00）稳定、可解释、零训练成本 | A ndcg@5 0.831 |
| BGE-Reranker 在该口径下为负贡献 | 消融 +0.142（移除后）、CI [0.036, 0.142] 反向 |
| 已训练代理标签模型（GB/MLP）口径内领先但循环性存疑 | E00x Task B 0.606–0.630；标签同源 |
| 完整两阶段 + 约束（E06）MRR 最高 | B mrr@5 0.938 |

## 3. 工程建议（当前可集成的推荐配置）

- **默认路径（保守）**：BM25 + TF-IDF 双路召回（RRF 融合）→ FeatureFusion 硬/软约束评分 → Top-K 输出 + 可解释明细。
  - 理由：口径内指标不劣于语义/精排方案；纯 CPU 毫秒级；无权重分发问题；可解释性完整。
- **可选增强（标注 EXPERIMENTAL，不作为已验证能力）**：BGE 向量召回融合（E04）；BGE-Reranker 仅在真实 Gold 验证其增益后再启用。
- **不推荐默认启用**：E05/E06 中的 Cross-Encoder 精排（当前证据为负贡献，且每对 61ms）。

| 条件 | 状态 |
