**`<学历描述>` 抽取槽位（【事实】）**

### 0.2 任务类型判定（【事实】）

| 判定 | 结论 | 依据 |
|---|---|---|
| 是否为 NER / 序列标注数据 | **否** | 无 token 级 BIO/BIOS 标注、无 span 起止偏移、无字符级标签序列 |
| 是否为 span 抽取数据 | **否** | 标签是归一化后的学历词枚举，不是原文子串偏移 |
| 最贴合的任务形态 | **信息抽取（生成式短答案抽取）** | 输出是受限词表上的短序列（`博士、硕士、本科`） |
| 备选形态 1 | **多标签分类** | 6 个 token 的多标签，可直接建模 |
| 备选形态 2 | **有序多分类** | 映射为最低学历层级（大专 < 本科 < 硕士 < 博士） |
| 备选形态 3 | **规则 + 模型混合** | `<学历描述>` 走规则、正文走模型兜底 |

**结论**：这是**信息抽取**数据，不是 NER 数据。**不能预设它是序列标注任务**。

### 0.3 标签来源追查（【事实】—— 本次审计最重要的发现之一）

在 `annotated/2w_0716_eval.csv` 与 `default/validation/4w_0708.csv` 按 `job_id` 对齐后：

| 检查 | 结果 |
|---|---:|
| `annotated` 的 `job_id` 全部在 `validation` 中 | **True（100%）** |
| `annotated.user` == `validation.user` | **100.00%** |
| `annotated.线上学历-旧的` == `validation.assistant` | **100.00%** |
| `annotated.模型结果-新的` == `validation.assistant` | 96.76% |
| `人工正确结果` == `validation.assistant`（736 行） | **45.92%** |
| `annotated.assistant` == `人工正确结果`（736 行） | 100.00% |

**推论链**

1. `validation.assistant` 与 `annotated.线上学历-旧的` **逐行 100% 相同** → default 三个切分的 `assistant` 标签就是**旧线上系统的输出**（伪标签 / 远监督），不是人工标注。
2. 人工复核的 736 行中，人工金标准与该伪标签**只有 45.92% 一致** → **约 54.08% 的既有标签与人工结论不符**。
3. `annotated.assistant` == `人工正确结果` → `annotated` 的 `assistant` 列是人工结果，而 default 三份的 `assistant` 是伪标签，**两处同名列含义不同**。

**736 行人工评测结果（按 token 集合比较，忽略顺序与分隔符差异）**

| 系统 | 与人工金标准一致 | 一致率 |
|---|---:|---:|
| `线上学历-旧的` | 338 | **45.92%** |
| `模型结果-新的` | 300 | **40.76%** |

交叉表：旧对新对 **0**、旧对新错 338、旧错新对 300、旧错新错 98。

> ⚠️ **正确解读**："旧对且新对 = 0" 是**机械结果**，不是统计发现：这 736 行上 `线上学历-旧的` 与 `模型结果-新的` **逐行无一相同**（字符串与 token 集合均 0% 相等），两者不可能同时等于金标准。**不得解读为两个系统在统计上互斥。**

**新模型的抽取错误形态（【事实】）**

- `模型结果-新的` 在 22,730 行上有 22 个唯一值，其中 **3 行是明显的抽取失败**，输出直接把岗位描述文本当答案（如 `学历、目标院校、语言、技能、性格等要求</岗位描述>\n<学历描述>本科</学历描述>`）
- 存在 `硕士、博士、博士、硕士` 这类**重复 token**输出（2 行）
- 错误方向：`new` 比金标准 token 更多的 72 行、更少的 **314 行** —— **系统性漏抽**，与"<学历描述> 只给最低学历"的机制吻合
- 数据中出现 `大四保研准硕士` 这类**词表外 token**（1 行），说明标签词表并非严格封闭

### 0.4 切分包含关系（【事实】—— 数据泄漏）

| 对 | `job_id` 重叠 | `user` 文本重叠 | 子集关系 |
|---|---:|---:|---|
| train ∩ validation | 0 | 1 | 互斥 ✅ |
| train ∩ test | 0 | 1 | 互斥 ✅ |
| **validation ∩ test** | **22,730（100% of test）** | **21,433（100% of test）** | **test ⊂ validation** ❌ |

**【事实】**：`test` 的 22,730 个 `job_id` 与 21,433 个唯一 `user` 文本**全部包含在 `validation` 中**。

**后果**：在 `validation` 上做模型选择 / 早停 / 超参搜索后再报 `test` 指标，**等价于在测试集上调参**，构成数据泄漏。必须重新切分。

**内部重复**：`user` 文本在 train/val/test 内部重复率 6.50% / 6.05% / 5.71%（同一岗位文本多行）。

## 1. 备选算法任务可行性

### 任务 A：岗位学历与技能信息抽取

| 项目 | 内容 |
|---|---|
| **可使用的数据源** | `job-education/default/train`(197,574) / `validation`(45,593) / `test`(22,730) / `annotated`(22,730，含 736 人工金标准) |
| **输入特征** | `user`：`<岗位名称>` + `<岗位描述>` + `<学历描述>` 三段 XML-like 文本（中位 324 字符，最长 7,694） |
| **可用监督标签** | `assistant`：6 token 词表上的多值枚举（`博士、硕士、本科` 等），多标签占 56.95% |
| **标签可信度** | **中—低**。train/val/test 的 `assistant` 是线上旧系统输出（伪标签），与 736 条人工金标准仅 **45.92%** 一致；只有 736 条是人工真值 |
| **推荐的模型方向** | ① 生成式短答案抽取（Seq2Seq，如 Chinese-T5 / mT5 / BART-Chinese）<br>② **多标签分类**（6 个 sigmoid 输出，最稳、最容易评估）<br>③ 规则 + 模型混合：`<学历描述>` 走规则映射，正文走模型兜底<br>④ 有序多分类（映射为最低学历层级） |
| **数据量是否足够** | **足够**。19.7 万训练样本，远超 6 token 多标签分类所需；即使是生成式微调也够 |
| **可能存在的数据泄漏** | ① `test ⊂ validation`（必须重切）<br>② `<学历描述>` 槽位本身就是上游抽取结果，属**先验线索泄漏**；若评估目的是"从原始 JD 抽取"，必须做去掉该槽位的消融<br>③ train/val/test 内部 `user` 文本重复 5.7~6.5%，同文本跨行 |
| **建议的评估指标** | **token 集合层面的 exact-match accuracy、micro/macro-F1、per-token recall**（`本科/硕士/博士/大专/学历不限/学历不明`）；另报"最低学历层级"的 ordinal accuracy 与 MAE；生成式模型需做输出规整后再评 |
| **主要实施风险** | ① 伪标签噪声 54%，直接训练会学到旧系统的系统性偏差（尤其是"<学历描述>当答案"的漏抽错误）<br>② 人工金标准只有 736 条，无法支撑全量微调<br>③ 词表外 token（`大四保研准硕士`）需设计兜底策略<br>④ 3 行脏输出说明生成式模型有溢出风险，需输出约束 |

> **技能信息抽取**：主匹配数据集的 `cv.clean_skills` / `job.clean_skills` 是**已抽好的技能列表**（`ast.literal_eval` 可还原），没有对应的原始 JD→技能标注对，**不能做技能抽取的监督训练**，只能做技能归一化 / 同义词合并 / 缺口分析（见任务 E）。

### 任务 B：简历—岗位匹配强度预测

| 项目 | 内容 |
|---|---|
| **可使用的数据源** | `cv.csv`(9,544) + `job.csv`(1,167) + `matches.csv`(122,560) |
| **输入特征** | 文本对（`resume_text` / `job_text`）、`clean_skills` 集合、`years_experience` vs `years_required`、两侧 `category`、两侧 768 维 embedding |
| **可用监督标签** | `label_strength`（3 档）或 `final_score`（连续）或 `candidate_rank`（组内序） |
| **标签可信度** | **低（作为"真实匹配"）/ 高（作为"复现该评分体系"）**。标签是公式派生：`semantic → raw → final → label`，复现率 100%。**不是人工标注，也不是真实招聘结果** |
| **推荐的模型方向** | ① **Learning-to-Rank**（LambdaRank / LambdaMART / BPR）—— 最贴合数据结构<br>② 回归 `final_score`（避开类别不平衡）<br>③ 双塔语义召回 + 轻量重排<br>④ 若坚持三分类：需分层采样 + macro-F1 |
| **数据量是否足够** | **足够训练，勉强够评估**。12.3 万 pair / 9,532 人 / 1,164 岗；但 `strong_positive` 仅 774 条，按候选人分组 5 折后每折约 155 条，`strong` 的 per-fold 指标不稳定 |
| **可能存在的数据泄漏** | ① **致命**：`final_score`/`raw_score`/`candidate_rank`/`candidate_rank_pct` 与标签同源，必须从特征中剔除<br>② 六维打分合起来决定 100% 权重链，也不能用<br>③ 预计算 embedding 经 `semantic_score` 参与标签生成（派生泄漏）<br>④ 行级随机切分下 99.6% 验证候选人、100% 验证岗位在训练集出现过 |
| **建议的评估指标** | **NDCG@k、MAP、MRR、Recall@k**（组内排序）；若做三分类用 macro-F1 / per-class recall / Cohen's κ / ordinal MAE；**禁止只报 overall accuracy**（全预测 medium 就有 57.6%） |
| **主要实施风险** | ① 目标泄漏：任何用到分数/排名字段的特征集都会得到虚假的高指标<br>② 无真实负例（见 `matching-label-analysis.md` 第 5 节）<br>③ `strong` 类 0.63%，类别极度不平衡<br>④ 60 个单记录候选人无法做组内排序<br>⑤ `weak` 与 `medium` 的分数边界仅 3.5e-7，本质不可分 |

### 任务 C：简历—岗位语义相似度计算

| 项目 | 内容 |
|---|---|
| **可使用的数据源** | `cv.embedding` / `job.embedding`（各 768 维，已 L2 归一化）；`matches.csv` 的 `semantic_score` |
| **输入特征** | 简历文本、岗位文本、两侧预计算向量 |
| **可用监督标签** | 无独立标签。`semantic_score` **就是**两侧向量余弦的仿射（`0.5·cos+0.5`，R²=1.0），用它作标签等于自证 |
| **标签可信度** | **作为"相似度真值"不可信**；作为"复现该向量空间"的代理标签可用 |
| **推荐的模型方向** | ① 直接用预计算向量做内积检索（**零训练基线**，务必先建）<br>② 对比学习（SimCSE / ESimCSE / CoSENT）微调中文句向量<br>③ Cross-Encoder 重排（BERT/RoBERTa 拼接打分） |
| **数据量是否足够** | 足够做对比学习（12.3 万正对 + 负采样）；但**缺少独立的相似度真值**，评估只能用下游任务代理 |
| **可能存在的数据泄漏** | 用 `semantic_score` 训练再用它评估 = 完全循环论证；必须换独立评估口径（人工小样本标注 / 下游排序指标） |
| **建议的评估指标** | STS 类指标（Spearman/Pearson）**仅在有独立真值时有效**；否则用下游 NDCG@k、Recall@k、以及人工标注的 500~1,000 组相似度 |
| **主要实施风险** | ① 无独立评估真值，是本任务最大的方法论风险<br>② 与 `skill_score` 负相关（−0.23），纯语义相似度会忽略技能匹配<br>③ RTX 2050 仅 4 GB 显存，Cross-Encoder 批量训练受限 |

### 任务 E：简历技能缺口分析

| 项目 | 内容 |
|---|---|
| **可使用的数据源** | `cv.clean_skills` / `job.clean_skills`（`ast.literal_eval` 可还原为 `list[str]`）、`matches.skill_score` |
| **输入特征** | 候选人技能集合、岗位技能集合 |

| **标签可信度** | 不适用（无监督 / 规则任务） |
| **推荐的模型方向** | ① **集合差 + 同义词归一**（规则，可解释性强，适合论文展示）<br>② 技能词嵌入聚类（把 `hadoop`/`big data` 归一）<br>③ 知识图谱 / 技能本体（如 O*NET 对齐）—— 工作量大 |
| **数据量是否足够** | 足够（9,544 简历 + 1,167 岗位的技能集合） |
| **可能存在的数据泄漏** | 低。但若用 `skill_score` 反推缺口规则，需注意它已参与标签生成 |
| **建议的评估指标** | 无金标准时只能做**人工抽检准确率**；或用"缺口技能能否提升 `skill_score`"做一致性检验 |
| **主要实施风险** | ① 技能词表噪声大（英文技能名、大小写、同义词）<br>② 无标注，评估只能靠人工<br>③ `cv.clean_skills` 有 20 行近似空 |

| **B. 匹配强度预测** | ★★★★☆ | ★★☆☆☆（公式派生） | ★★★★★ | ★★★☆☆ | P1（需严格剔除泄漏字段） |

**为什么任务 A 应当优先**：它是唯一一个**标签由真实语义需求定义**（而非公式派生）、**数据量充足**（19.7 万）、**评估口径清晰**（6 token 多标签 F1）的任务。缺点是标签为伪标签、真值只有 736 条，但这可以通过"弱监督预训练 + 736 条人工金标准评估"的方式正面处理。

## 3. 五个重点问题的直接回答

### 问题一：现有数据能够支持哪些真实的监督学习任务？

**能支持（有可用监督信号）**

1. **岗位学历信息抽取 / 多标签分类**（任务 A）—— 19.7 万样本，6 token 封闭词表，56.95% 多标签。这是数据最强的一项。
2. **简历—岗位组内排序**（任务 D）—— `candidate_rank` 是确定性的组内序（9,532/9,532 组复现），9,472 个候选人有 ≥2 条可排序记录。
3. **匹配强度回归**（任务 B 的回归形式）—— 用 `final_score` 连续值做目标，避开类别不平衡。

**不能支持（缺真实监督信号）**

4. 真实匹配结果二分类 —— 无任何真实投递/录用/面试结果，`matches.csv` 只有公式派生的三档正样本。
5. 招聘诈骗识别的监督学习 —— `scam_probability` 只有 9 个离散值、全是 10 的倍数、无人工真值列（详见 `dataset-profile.md` 第 5 节）。
6. 序列标注 / NER —— 学历数据无 token 级标注、无 span 偏移、无 BIO 标签。
7. 技能信息抽取 —— `clean_skills` 已是抽取结果，无原始 JD→技能标注对。

**关键限定**：第 1~3 项"能支持"的含义是**能训练出可评估的模型**，不等于能训练出"预测真实世界匹配结果"的模型。B/D 的标签本质是复现一个评分体系。

### 问题二：六维评分与 `label_strength` 是否存在目标泄漏风险？

**是，存在完全确定的目标泄漏，已逐级反推证实。**

完整派生链（每一环误差都在机器精度量级）：

```
semantic_score = 0.5 × cosine(cv_emb, job_emb) + 0.5          R²=1.0,  max|err|=2.4e-7
raw_score      = 0.25·semantic + 0.35·skill + 0.20·position
               + 0.10·category + 0.05·experience + 0.05·education   max|err|=2.22e-16
final_score    = 0.7 × raw_score + 0.3 × candidate_rank_pct    R²=1.0,  max|err|=8.88e-16
label_strength = weak(<0.58) / medium(0.58~0.68) / strong(≥0.68)   复现率 100%, 例外 0 行
candidate_rank = 组内 final_score 降序名次                       9532/9532 组复现
```

**实验证据**

- 仅用 `final_score` 单特征的深度 2 决策树，训练准确率 **1.000000**
- 用六维打分的深度 4 决策树，训练准确率仅 0.764246
- 加回 `final_score` 后立刻回到 1.000000

**必须从特征中剔除的字段**：`final_score`、`raw_score`、`candidate_rank`、`candidate_rank_pct`、六维打分（`semantic_score`、`skill_score`、`position_score`、`category_score`、`experience_score`、`education_score`）。

**附带风险**：预计算 embedding 经 `semantic_score` 参与标签生成，属派生信息泄漏；行级随机切分下 99.6% 验证候选人、100% 验证岗位在训练集出现过。

### 问题三：当前数据是否足以训练一个可评估的简历—岗位匹配模型？

**有条件足够 —— 足够训练与评估一个"可复现的匹配/排序模型"，不足以支撑"预测真实匹配结果"的结论。**

**够用的部分（【事实】）**

| 指标 | 数值 |
|---|---:|
| 匹配记录 | 122,560 |
| 候选人 | 9,532（外键 100% 命中） |
| 岗位 | 1,164（外键 100% 命中） |
| 重复组合 / 标签冲突 | 0 / 0 |
| 每候选人岗位数中位 | 11 |
| 有 ≥2 条记录可排序的候选人 | 9,472 |
| 预计算向量 | 9,544 + 1,167 个 768 维，100% 可解析 |

**不够用的部分（【事实】）**

| 问题 | 数值 | 影响 |
|---|---|---|
| 无真实负例 | 0 个显式负标签；未观测组合 11,015,288（98.90%） | 无法做二分类，必须自建负例 |
| `strong_positive` 稀缺 | 774 条（0.63%），medium/strong = 91.3:1 | 三分类指标不稳定 |
| `weak`↔`medium` 边界 | 分数间隙仅 3.5e-7 | 两档本质不可分 |
| 单记录候选人 | 60 个 | 无法做组内排序 |
| 覆盖率 | 观测组合仅占全交叉积 1.10% | 召回类指标只能在观测子集上算 |
| 标签来源 | 公式派生 | 不能声称"真实匹配" |

**结论**：足够支撑一个**可评估、可复现的匹配/排序模型**（推荐 Learning-to-Rank + 双塔召回）；但必须在论文中明确声明标签是评分体系的派生结果，模型能力的结论只能是"复现并泛化该评分体系"，不能是"预测真实招聘匹配结果"。

### 问题四：哪些数据问题必须在模型训练前解决？

按优先级：

| # | 问题 | 影响 | 处置 |
|---|---|---|---|
| 1 | **目标泄漏字段** | 用分数/排名字段预测标签 = 100% 虚假准确率 | 从特征集中剔除 10 个字段（见问题二） |
| 2 | **`job-education` 的 test ⊂ validation** | 在 validation 选模型后报 test = 测试集调参 | 从 validation 剥离 test 的 22,730 个 `job_id`，或合并后按 `job_id` 重新 8:1:1 分层切分 |
| 3 | **`job-education` 标签是伪标签** | 与 736 条人工真值仅 45.92% 一致，54.08% 不符 | 明确采用"弱监督预训练 + 人工 736 条评估"，或只用 736 条 + 主动学习扩充 |
| 4 | **`matches.csv` 无真实负例** | 无法做二分类 | 采用 BPR/成对排序为主，或按候选人做组内负采样（见 `matching-label-analysis.md` 5.2） |
| 5 | **`strong_positive` 仅 774 条（0.63%）** | 三分类指标不稳定 | 改用回归/排序目标，或分层采样 + macro-F1 |
| 6 | **行级随机切分泄漏** | 99.6% 验证候选人、100% 验证岗位在训练集出现 | 按 `candidate_id` 分组切分，并加 `job_id` 冷启动切分 |
| 7 | **`all_df.csv` 整行重复 25,433 行（10.12%）** | 重复样本扭曲分布 | 去重并保留去重映射 |
| 8 | **`job.csv` 的 `education_text` 疑似复制 `job_description`** | 特征冗余 | 建模前确认并去重 |
| 9 | **`user_short2` 整列全空** | 无效字段 | 直接丢弃 |
| 10 | **`<学历描述>` 槽位是上游抽取结果** | 若评估"从原始 JD 抽取"则属先验泄漏 | 做去掉该槽位的消融实验 |
| 11 | **极端数值**：`job_salary` 最大 4,597,500、`years_required` 最大 40 | 离群值影响 | 分位数截断 / Winsorize；`years_required` 语义存疑需确认 |
| 12 | **类别不平衡**：`cv.inferred_category` IT 占 85.3% | 小类无统计意义 | 分层评估，或合并小类 |

### 问题五：下一阶段数据预处理与数据划分应当采用什么方案？

#### 5.1 数据划分

**主匹配数据集（`matches.csv`）—— 三套评估口径**

| 划分 | 做法 | 用途 |
|---|---|---|
| **S1 候选人冷启动（主指标）** | `GroupShuffleSplit(groups=candidate_id)` 8:1:1，固定 `random_state` | 评估对**未见候选人**的泛化 |
| **S2 岗位冷启动** | `GroupShuffleSplit(groups=job_id)` 8:1:1 | 评估对**未见岗位**的泛化 |
| **S3 双冷启动（最严）** | 先按 `candidate_id` 切，再在训练集内按 `job_id` 切，保证两组在三集合都互斥 | 最保守的泛化指标 |

- **禁止**行级随机切分。
- 切分清单落盘到 `data/splits/`（`{candidate_id | job_id} → split` 映射 + 随机种子 + 生成脚本版本），JSON 记录以便复现。
- 每折报告 `strong_positive` 支持数；某折 < 30 条则该折 `strong` 指标不具统计意义。
- 60 个单记录候选人自动排除出排序评估，单独统计。

**学历数据（`job-education`）**

1. 从 `validation` 中剥离 `test` 的 22,730 个 `job_id`（保持 `test` 独立）；
2. 或把 default 三份按 `job_id` 合并后**重新做 8:1:1 分层切分**（按标签 token 数分层）；
3. **`annotated` 的 736 条人工金标准单独留作最终测试集**，不参与任何训练/调参；
4. 内部 `user` 文本重复率 5.7~6.5%，切分时按**归一化后的 `user` 文本哈希**分组，避免同文本跨集合。

#### 5.2 数据预处理

| 步骤 | 具体做法 |
|---|---|
| **向量解析** | 把 `cv.embedding` / `job.embedding` 从字符串解析为 `float32` 矩阵，落盘 `data/processed/{cv,job}_emb.npy` + `*.index.npy`（id 映射），避免重复解析 |
| **技能归一** | `clean_skills` 用 `ast.literal_eval` 还原为 `list[str]`；统一小写、去空白、同义词合并（`big data`/`hadoop`、`js`/`javascript`）；建 `skill_vocab.json` |
| **学历标签规范化** | 统一为 6 token 有序多标签：`[博士, 硕士, 本科, 大专, 学历不限, 学历不明]`；用 token 集合比较（忽略顺序/分隔符）；对 `大四保研准硕士` 等词表外 token 设计兜底（映射到 `硕士` 或标记 `UNKNOWN`） |
| **文本清洗** | 保留 `<岗位名称>/<岗位描述>/<学历描述>` 标签结构（它们是重要线索）；做去重（按归一化文本哈希）；控制最大长度（`resume_text` 已被上游截到 3,000、`job_text` 到 3,500） |
| **去重** | `all_df.csv` 整行去重（25,433 行）；`matches.csv` 已无重复组合，无需处理 |
| **离群值** | `job_salary` 分位数截断（p99 = 375,000）；`years_required` 语义确认后再用 |
| **字段剔除** | 丢弃 `user_short2`（整列空）；确认并处理 `job.csv.education_text` 与 `job_description` 的冗余 |
| **泄漏字段隔离** | 把 `final_score`/`raw_score`/`candidate_rank`/`candidate_rank_pct`/六维打分单独存为 `label_derived/` 目录，与特征目录物理隔离 |

#### 5.3 负采样（第三阶段实施，本阶段不生成）

- **主方案**：BPR 成对排序 —— 只用 `candidate_rank` 组内序构造偏好对，不显式建负类
- **辅助方案**：按候选人从其未观测岗位中随机抽 k 个作负例（k = 5~10），用于二分类消融
- **难负例**：从 `weak_positive` 的低分位取样，仅用于排序模型的消融
- 所有负采样必须在**训练集内部**进行，切分完成后再采样，避免负例跨集合

## 4. 建议的下一步（第三阶段）

1. **先做零训练基线**：直接用预计算向量做内积检索，报告 NDCG@k / Recall@k。这个基线是所有后续模型的下界。
2. **任务 A 立项**：学历多标签分类（6 sigmoid）+ 生成式抽取双路线，用 736 条人工金标准做最终评估。
3. **任务 D 立项**：BPR / LambdaRank，按 `candidate_id` 分组切分。
4. **明确不做**：真实匹配二分类、诈骗识别监督学习、NER —— 除非补充人工标注。
5. **不训练大语言模型**：任务 A 用 6 token 多标签分类或小型 Seq2Seq 即可；4 GB 显存（RTX 2050）也不支持大模型全参微调。是否需要更大模型应由基线实验结果决定，而非预设。

## 5. 本阶段未解决的问题（诚实记录）

5. 生成 `scam_probability` 的模型/规则与校准含义未知。
6. `job-education` 中旧线上系统（`线上学历-旧的`）本身的准确率只有 45.92%（相对 736 条人工真值），但该系统的设计未知。

8. `job.csv.years_required`（均值 14.3、最大 40）的语义存疑，需向数据源确认。
