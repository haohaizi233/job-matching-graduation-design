## 3. 空间一致性：`cv` 与 `job` 向量是否同空间

**【事实】**：同维度（768）、同为单位向量、分量分布一致 —— 三条都指向同一空间。更强的证据来自下一节。

**随机配对基线**（1,167 组随机 `cv × job` 配对）

| 统计 | 值 |
|---|---:|
| 余弦均值 | 0.424421 |
| 余弦标准差 | 0.099092 |
| 余弦 min / p50 / max | 0.141726 / 0.421766 / 0.761850 |

**匹配对**（3,000 组 `matches.csv` 中的真实组合）

| 统计 | 值 |
|---|---:|
| 余弦均值 | **0.564133** |
| 余弦 min / max | 0.215364 / 0.835392 |
| `semantic_score` 均值 | 0.782067 |

**【事实】**：匹配对余弦均值 0.564 显著高于随机对 0.424（提升 0.14，约 1.4 倍标准差），说明**两侧向量确实处于同一语义空间，且对"人岗相关性"有区分能力**。

## 4. 向量与 `semantic_score` 的关系：**完全确定的仿射变换**

在 3,000 组匹配对上，把 `cosine(cv_emb, job_emb)` 与 CSV 中的 `semantic_score` 做回归：

| 拟合方向 | slope | intercept | R² | max\|residual\| |
|---|---:|---:|---:|---:|
| `semantic_score ~ cosine` | **0.49999999** | **0.50000000** | **1.00000000** | 2.4e-07 |
| `cosine ~ semantic_score` | 2.00000002 | −1.00000001 | 1.00000000 | 4.8e-07 |

Pearson = **1.000000**，Spearman = **1.000000**。

### 【事实】公式

```
semantic_score = 0.5 × cosine(cv_embedding, job_embedding) + 0.5
等价反解：cosine = 2 × semantic_score − 1
```

这是本次审计**最强的一条确定性结论**：`semantic_score` 不是一个独立的打分，它就是两侧预计算向量的余弦相似度做了一次 `[−1, 1] → [0, 1]` 的线性映射。残差 2.4e-07 属于 CSV 单精度写入的舍入误差。

### 与其它字段的相关性（【事实】）

| 相关对 | Pearson |
|---|---:|
| `cosine` vs `semantic_score` | **1.000000** |
| `cosine` vs `skill_score` | **−0.229685** |
| `cosine` vs `final_score` | 0.291124 |

**【事实】**：`cosine` 与 `skill_score` 的 Pearson 是 **−0.23（负相关）**。

**【推断】**：embedding 与技能重叠分数**不是同一来源、也不编码相同信息**。向量主要承载文本语义相似度，技能重叠由 `clean_skills` 的符号匹配另行计算。这排除了"embedding 是技能特征向量"的假设。

## 5. 向量类型判断：单独的简历向量 / 岗位向量 / 联合表示？

**【事实】**

| 判断项 | 结论 | 依据 |
|---|---|---|
| 是否为联合 pair 级表示 | **否** | `cv.csv` 与 `job.csv` 各自持有独立 `embedding` 列；`matches.csv` **不持有任何向量字段** |
| `cv.embedding` 的语义 | 候选人侧（简历）表示 | 一行一个 `candidate_id`，9,544 个唯一向量 |
| `job.embedding` 的语义 | 岗位侧（职位）表示 | 一行一个 `job_id`，1,167 个唯一向量 |
| 两侧是否同编码器 | **高度可能同塔**（【推断】） | 同维度、同单位范数、同分量标准差 0.036084、余弦可直接比较 |

**【未知】**：无法从数据确定是"单塔共享编码器"还是"双塔但训练到同一空间"。两者在向量层面表现一致，数据不提供区分依据。

## 6. Embedding 来源判断

### 【事实】—— 数据与数据卡片明确说明

1. `cv.csv` / `job.csv` 的 `embedding` 均可 100% 解析为 768 维 float32 向量。
2. 两表向量维度一致（768）。
3. 数据集 README（`data/raw/job-resume-matching/README.md`）字段表中明确写：`embedding` = **"Precomputed 768-dimensional text embedding"**。
4. README 的 **Limitations** 章节明确写：**"The embedding model used to create the stored vectors is not specified in the dataset files."**（数据集文件中未指明生成这些向量的 embedding 模型）。
5. README 的 Load Embeddings 示例用 `ast.literal_eval` 解析，与实测一致。

### 【推断】—— 有实验支持

- `semantic_score = 0.5 × cosine + 0.5`（R² = 1.0），说明向量是**为语义相似度检索而生成的句向量**，并已做过 L2 归一化。
- 向量呈单位球面均匀分布（分量 std 恰为 `1/√768`），符合 Transformer 句向量 mean-pooling / CLS 后归一化的典型形态。
- 匹配对余弦显著高于随机对，说明向量对"人岗相关性"有实际区分度，不是随机或退化向量。

### 【未知】—— 无法从数据本身确定

- **具体编码模型**（架构、版本、训练语料）。
- 编码输入是 `resume_text` / `job_description` **原文**，还是 `job_text` / `clean_skills` 等**清洗后拼接文本**。
- 单塔（共享编码器）还是双塔（两个编码器）。
- 是否做过领域继续预训练或对比学习微调。

### 【严禁声称】

- ❌ **不能仅凭"768 维"就断定编码模型是 BERT / RoBERTa / MPNet / Sentence-BERT 中的任何一个**。768 是 BERT-base 系列的隐藏维度，但大量模型共享该维度，数据本身不提供任何判别依据。README 也明确声明未指定模型。
- ❌ 不能把 embedding 当作独立于标签的"原始特征"：它经 `semantic_score → raw_score → final_score → label_strength` 参与了标签生成，属派生信息链的一环。
- ❌ 不能声称向量是"简历—岗位联合匹配表示"：`matches.csv` 中没有 pair 级向量。

## 7. 对后续建模的直接影响

| 影响 | 说明 |
|---|---|
| **可直接用于双塔检索** | 向量已 L2 归一化，可直接做内积检索 / ANN 索引（FAISS、Annoy 等） |
| **不可用于"重新定义 semantic_score"** | 若目标是复现数据集的 `semantic_score`，直接用余弦即可，无需训练 |
| **用 embedding 预测 `label_strength` = 泄漏** | 该向量经 `semantic_score` 参与标签生成，属于派生特征泄漏 |
| **可作为语义相似度任务的特征** | 若要做"简历—岗位语义相似度"（任务 C），需自行构造独立的评估标签，不能复用 `semantic_score` |
| **可作为下游模型的初始化特征** | 在剔除 `semantic_score` 等派生字段的前提下，embedding 可作为独立输入；但必须在报告中说明其与标签的派生关系 |
| **解析成本已知** | 9,544 + 1,167 条字符串向量全量解析约需 190 MB 内存；建议预解析为 `.npy` 落盘到 `data/processed/`，避免重复解析 |

## 8. 结论摘要

**【事实】** 768 维、float32、100% 可解析、L2 单位范数、无零向量 / NaN / Inf / 重复向量；`cv` 与 `job` 向量同维度同分布；`semantic_score = 0.5 × cosine + 0.5` 精确成立（R² = 1.0）；`cosine` 与 `skill_score` 负相关（−0.23）。

**【推断】** 两侧向量共享同一语义空间、极可能同编码器；向量是为语义相似度检索而生成的句向量；`matches.csv` 中没有 pair 级联合表示。

**【未知】** 编码模型、编码输入、单塔/双塔、是否微调 —— README 明确声明模型未指定，数据本身也不提供判别依据。**768 维不足以推断编码模型。**
